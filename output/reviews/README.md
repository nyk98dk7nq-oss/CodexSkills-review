# レビュー結果

レビュー実行後の結果記入済みチェックリストと Markdown サマリーを保存するフォルダです。

レビュー実行時のローカル時刻を `yyyyMMddhhmm` 形式にしたフォルダを作成し、その中へ `input/checklists/` のチェックリストを元のファイル名でコピーします。旧形式の `.xls` は `.xlsx` へ変換し、同名または大文字・小文字だけが異なる名前が衝突する場合は、2件目以降へ `__2`、`__3` の連番を付けます。

```text
output/reviews/
└─ 202608171930/
   ├─ summary.md
   └─ <チェックリストの元ファイル名>.xlsx
```

コピーしたチェックリストの既存列の右側へ、レビュー対象ファイル1件につき次の3列を追加します。

1. `レビュー対象ファイル名`
2. `レビュー結果`
3. `レビューコメント`

チェック項目の各行について、対象ファイル数分の結果を記入します。レビュー結果は `適合`、`不適合`、`対象外`、`要確認` の4種類です。レビューコメントには、AI が判定した根拠と確認可能な該当箇所を記載します。

`summary.md` には、使用したチェックリスト・参考資料・対象ファイル、4種類の判定件数を記載します。特にすべての `不適合` 項目を中心に、次をまとめます。

- チェック項目とチェックリスト内の位置
- レビュー対象ファイル名
- 不適合とした具体的な根拠
- AIによる具体的で実行可能な改善案

不適合がない場合も `summary.md` を作成し、「不適合なし」と記載します。根拠が不足している場合は改善内容を断定せず、必要な情報を `要確認` として記載します。

このフォルダへ、実行前にレビュー用の入力ファイルを置く必要はありません。生成された結果は通常の Git 管理対象になりません。
