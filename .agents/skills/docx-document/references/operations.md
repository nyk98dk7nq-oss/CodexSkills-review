# DOCX操作仕様

入力と出力には異なる未作成パスを指定する。既存の出力は上書きしない。出力パス自体または既存祖先がシンボリックリンクなら拒否し、壊れたリンクも既存出力として扱う。JSONは操作の配列、または `operations` 配列を持つオブジェクトとする。記載順に操作する。

```json
{
  "operations": [
    {"op": "replace_text", "old": "旧名称", "new": "新名称", "count": 1},
    {"op": "add_paragraph", "text": "改訂理由", "style": "Heading 2"},
    {"op": "set_table_cell", "table": 1, "row": 2, "column": 3, "text": "更新値"}
  ]
}
```

- `replace_text`: 本文、表、ヘッダー、フッターから文字列を置換する。`count` は省略可能で、指定時は文書全体での最大置換回数とする。複数runにまたがる文字列も置換するが、該当段落の文字装飾は先頭runへまとめられるため出力を目視確認する。対象文字がハイパーリンクを含む段落にある場合は、リンク関係を壊さないため操作全体を拒否する。
- `add_paragraph`: 文書末尾へ段落を追加する。`style` は省略できる。文書に存在しないスタイル名はエラーになる。
- `set_table_cell`: 本文にある表のセルを置換する。`table`、`row`、`column` はすべて1始まりとする。
- 対象が存在しない操作、範囲外の索引、上記以外の操作は拒否する。

Markdown変換では段落と表に1始まりの位置を付ける。ハイパーリンクは表示文字とURLを文書順にMarkdownリンクとして記録する。リストは段落styleと`numPr`を確認し、箇条書き・番号付き、レベル、`numId`、番号形式を可能な範囲で記録する。

`--images-dir` を指定した場合、画像ディレクトリ、予定画像、それらの既存祖先にあるシンボリックリンクを拒否する。全画像の出力予定を先に検証し、既存、壊れたリンク、または相互に重複するパスが1件でもあれば、画像もMarkdownも作らない。成功時だけ埋め込み画像を抽出し、Markdown出力位置からの相対リンクを記録する。
